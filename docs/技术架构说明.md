# 中药材销售平台 技术架构说明

## 一、三端权限模型与数据隔离

### 1.1 角色定义

系统采用三端分离架构，包含三种用户角色，定义在 [Constants.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/common/Constants.java) 中：

| 角色 | 常量 | 说明 | 前端应用 |
|------|------|------|----------|
| 管理员 | `ROLE_ADMIN` | 平台超级管理员，管理全站 | frontend-admin |
| 商户 | `ROLE_MERCHANT` | 药材供应商，管理自己的商品和订单 | frontend-user (merchant 模块) |
| 采购商 | `ROLE_PURCHASER` | 药材买家，下单购买 | frontend-user (purchaser 模块) |

### 1.2 认证机制

#### 1.2.1 JWT Token 认证
采用 JWT + Redis 双重验证机制，核心实现在 [JwtUtil.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/util/JwtUtil.java) 和 [AuthInterceptor.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/interceptor/AuthInterceptor.java)。

**Token 生成逻辑**（`JwtUtil.generateToken`）：
- Payload 包含：`userId`、`username`、`role`
- 签名算法：HS512
- 有效期：配置项 `jwt.expiration` 控制

**认证流程**（`AuthInterceptor.preHandle`）：
1. 从请求头 `Authorization` 提取 Bearer Token
2. 校验 Token 是否过期
3. 校验 Redis 中是否存在该 Token（key: `token:{userId}`），实现登出失效
4. 解析 Token，将用户信息存入 ThreadLocal

#### 1.2.2 登录流程
登录接口由 [AuthServiceImpl.login](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/service/impl/AuthServiceImpl.java#L45-L114) 实现，根据传入的 `role` 参数分发到不同用户表查询：

- ADMIN → 查询 `admin_info` 表
- MERCHANT → 查询 `merchant_info` 表（需审核通过且未禁用）
- PURCHASER → 查询 `purchaser_info` 表

登录成功后：
- 生成 JWT Token
- Token 存入 Redis，有效期 24 小时
- 返回用户基本信息 + Token

#### 1.2.3 拦截器配置
在 [WebMvcConfig.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/config/WebMvcConfig.java) 中配置拦截规则：

```java
registry.addInterceptor(authInterceptor)

                "/uploads/**",   // 静态资源

        );
```

### 1.4 数据隔离机制

系统通过**URL 路径隔离 + Service 层参数校验**实现数据隔离，无全局角色拦截器，各 Controller 自行处理权限。

#### 1.4.1 路径隔离
三个角色的接口分别在不同 Controller 下，使用独立 URL 前缀：

| 角色 | Controller | URL 前缀 |
|------|------------|----------|
| 管理员 | [AdminController](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/controller/AdminController.java) | `/admin/**` |
| 商户 | [MerchantController](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/controller/MerchantController.java) | `/merchant/**` |

#### 1.4.2 商户侧数据隔离
商户只能操作自己的数据，通过 `UserContext.getUserId()` 作为过滤条件：


**示例 - 发货校验**（`OrderServiceImpl.shipOrder`）：

```java
OrderInfo order = orderMapper.selectById(orderId);
if (order == null || !order.getMerchantId().equals(merchantId)) {
    throw new BusinessException("订单不存在或无权操作");
}
```

#### 1.4.3 采购商侧数据隔离
采购商只能操作自己的购物车、订单、地址等：

**示例 - 购物车列表**（`PurchaserController.cartList`）：
```java
return Result.success(cartService.list(UserContext.getUserId()));
```

**示例 - 支付校验**（`OrderServiceImpl.payOrder`）：
```java
OrderInfo order = orderMapper.selectById(orderId);
if (order == null || !order.getPurchaserId().equals(purchaserId)) {
    throw new BusinessException("订单不存在或无权操作");
}
```

#### 1.4.4 管理员侧数据隔离
管理员可查看全站数据，不做用户维度过滤。

## 二、交易全流程代码流转

交易流程涉及：购物车 → 下单 → 支付 → 发货 → 收货 → 评价，共 6 个核心状态。

### 2.1 订单状态定义

订单状态常量定义在 [Constants.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/common/Constants.java#L17-L22)：

| 状态值 | 常量 | 说明 |
|--------|------|------|
| 0 | `ORDER_STATUS_UNPAID` | 待支付 |
| 1 | `ORDER_STATUS_PAID` | 已支付/待发货 |
| 2 | `ORDER_STATUS_SHIPPED` | 已发货 |
| 3 | `ORDER_STATUS_RECEIVED` | 已收货 |
| 4 | `ORDER_STATUS_COMPLETED` | 已完成（当前未实际使用） |
| 5 | `ORDER_STATUS_CANCELLED` | 已取消 |

### 2.2 数据模型

#### 2.2.1 订单主表
[OrderInfo.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/entity/OrderInfo.java) 核心字段：

- `id`：主键
- `orderNo`：订单号（格式：`ORD` + 时间戳 + 4位随机数）
- `purchaserId`：采购商ID
- `merchantId`：商户ID（一单对应一个商户）
- `totalAmount`：订单总金额
- `orderStatus`：订单状态
- `payTime` / `shipTime` / `receiveTime`：各环节时间戳
- `trackingNo`：物流单号
- `receiverName` / `receiverPhone` / `receiverAddress`：收货信息快照

#### 2.2.2 订单明细表
[OrderDetail.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/entity/OrderDetail.java) 核心字段：

- `orderId`：关联订单ID
- `medicineId`：药材ID
- `medicineName` / `medicineImage`：商品信息快照
- `quantity`：数量
- `price` / `subtotal`：单价与小计
- `rating` / `review` / `reviewTime`：评价信息

#### 2.2.3 购物车表
[CartInfo.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/entity/CartInfo.java)：

- `purchaserId`：采购商ID
- `medicineId`：药材ID
- `merchantId`：商户ID（冗余，便于按商户分组下单）
- `quantity`：数量

### 2.3 流程详解

#### 2.3.1 购物车阶段

**核心服务**：[CartServiceImpl.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/service/impl/CartServiceImpl.java)

**主要操作**：
- `add()`：加入购物车，同商品累加数量
- `updateQuantity()`：修改数量（≤0 时删除）
- `delete()`：删除单项
- `clear()`：清空购物车
- `list()`：查询购物车列表（关联商品信息）

**数据隔离**：所有操作均校验 `purchaserId` 归属。

#### 2.3.2 下单阶段

**入口**：`PurchaserController.createOrder` → `OrderServiceImpl.createOrder`

**核心逻辑**（[OrderServiceImpl.java#L99-L189](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/service/impl/OrderServiceImpl.java#L99-L189)）：

1. **地址校验**：验证收货地址存在且属于当前用户
2. **按商户分组**：将购物车商品按 `merchantId` 分组，拆分成多个子订单
3. **库存校验与扣减**：
   - 查询每个商品的库存
   - 库存不足抛出异常
   - 扣减库存（`inventory.stockQuantity -= quantity`）
   - 增加销量（`medicine.salesCount += quantity`）
4. **生成订单**：
   - 生成订单号：`ORD` + yyyyMMddHHmmss + 4位随机数
   - 计算总金额
   - 写入 `order_info` 表
   - 批量写入 `order_detail` 表（快照商品信息）
5. **发送通知**：给商户发送新订单通知
6. **返回**：返回第一个订单ID

**事务**：整个方法标注 `@Transactional`，保证原子性。

#### 2.3.3 支付阶段

**入口**：`PurchaserController.payOrder` → `OrderServiceImpl.payOrder`

**逻辑**（[OrderServiceImpl.java#L192-L210](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/service/impl/OrderServiceImpl.java#L192-L210)）：

1. 校验订单归属和状态（必须是 `UNPAID`）
2. 更新状态为 `PAID`，记录 `payTime`
3. 记录推荐订单转化（用于推荐算法统计）

> 注：当前为模拟支付，无真实支付网关接入。

#### 2.3.4 发货阶段

**入口**：`MerchantController.shipOrder` → `OrderServiceImpl.shipOrder`

**逻辑**（[OrderServiceImpl.java#L212-L226](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/service/impl/OrderServiceImpl.java#L212-L226)）：

1. 校验订单归属（商户ID匹配）
2. 校验状态（必须是 `PAID`）
3. 更新状态为 `SHIPPED`
4. 记录 `shipTime` 和 `trackingNo`（物流单号）

#### 2.3.5 收货阶段

**入口**：`PurchaserController.receiveOrder` → `OrderServiceImpl.receiveOrder`

**逻辑**（[OrderServiceImpl.java#L228-L241](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/service/impl/OrderServiceImpl.java#L228-L241)）：

1. 校验订单归属
2. 校验状态（必须是 `SHIPPED`）
3. 更新状态为 `RECEIVED`
4. 记录 `receiveTime`

#### 2.3.6 评价阶段

**入口**：`PurchaserController.reviewOrder` → `OrderServiceImpl.reviewOrder`

**逻辑**（[OrderServiceImpl.java#L271-L289](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/service/impl/OrderServiceImpl.java#L271-L289)）：

1. 根据 `orderDetailId` 查询订单明细
2. 校验订单归属
3. 校验状态（必须 ≥ `RECEIVED`）
4. 更新明细的 `rating`、`review`、`reviewTime`

> 注：评价是针对订单明细（商品维度），而非整个订单。

#### 2.3.7 取消订单

**入口**：`PurchaserController.cancelOrder` → `OrderServiceImpl.cancelOrder`

**逻辑**（[OrderServiceImpl.java#L243-L269](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/service/impl/OrderServiceImpl.java#L243-L269)）：

1. 校验订单归属和状态（只能取消 `UNPAID` 状态）
2. **库存回滚**：遍历订单明细，将数量加回库存
3. 更新状态为 `CANCELLED`

## 三、质量追溯模块

### 3.1 数据结构

追溯相关字段直接挂在药材表上，定义在 [MedicineInfo.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/entity/MedicineInfo.java) 和数据库表 [schema.sql](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/resources/schema.sql#L70-L92)。

#### 3.1.1 核心字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `trace_code` | VARCHAR(100) | 质量追溯码 |
| `trace_info` | TEXT | 追溯信息（文本/JSON格式） |
| `origin` | VARCHAR(100) | 产地 |
| `quality_grade` | VARCHAR(20) | 质量等级 |

#### 3.1.2 追溯码生成规则

在 [MedicineServiceImpl.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/service/impl/MedicineServiceImpl.java) 的 `create()` 和 `adminCreate()` 方法中自动生成：

```java
if (medicine.getTraceCode() == null || medicine.getTraceCode().trim().isEmpty()) {
    medicine.setTraceCode("TC" + UUID.randomUUID().toString().replace("-", "").substring(0, 16).toUpperCase());
}
```

**格式**：`TC` + 16位大写十六进制字符（UUID 截取），例如 `TC550E8400E29B41D`

### 3.2 查询链路

追溯信息没有独立的查询接口，而是随药材详情一并返回。

#### 3.2.1 查询入口

- **公开接口**：`/common/medicines/{id}`（CommonController，未在本次重点分析范围内）
- **采购商接口**：`/purchaser/medicines/{id}` → `PurchaserController.medicineDetail`
- **商户接口**：`/merchant/medicines/{id}` → `MerchantController.medicineDetail`
- **管理员接口**：`/admin/medicines/{id}` → `AdminController.medicineDetail`

以上均调用 `MedicineService.getDetail(id)`。

#### 3.2.2 服务层实现

[MedicineServiceImpl.getDetail](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/backend/src/main/java/com/medicine/sales/service/impl/MedicineServiceImpl.java#L60-L95)：

1. **缓存命中检查**：Redis key `medicine:{id}`，有效期 2 小时
2. **数据库查询**：`medicineMapper.selectById(id)`
3. **库存关联查询**：从 `inventory_info` 表查询库存和预警阈值
4. **组装 VO**：`BeanUtils.copyProperties` 自动复制 `traceCode`、`traceInfo` 等字段
5. **写入缓存**：返回结果存入 Redis

#### 3.2.3 前端展示

在用户端 [MedicineDetail.vue](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01267/app-01267-winter/frontend-user/src/views/MedicineDetail.vue) 中通过 Tab 切换展示：

```html
  <div class="tab-content">
    <p v-if="medicine.traceInfo">{{ medicine.traceInfo }}</p>
    <el-empty v-else description="暂无溯源信息" />
  </div>

```

展示位置：药材详情页 → "溯源信息" Tab 页。

### 3.3 管理与维护

追溯信息的维护通过药材编辑接口完成：

- **商户创建/编辑**：`MerchantController.createMedicine` / `updateMedicine` → `MedicineService.create` / `update`
- **管理员创建/编辑**：`AdminController.createMedicine` / `updateMedicine` → `MedicineService.adminCreate` / `adminUpdate`

提交的 DTO/Entity 中可包含 `traceCode` 和 `traceInfo` 字段，直接持久化到 `medicine_info` 表。

### 3.4 模块特点

1. **轻量设计**：无独立的追溯数据表和服务，作为药材信息的扩展字段存在
2. **文本化存储**：`trace_info` 为 TEXT 类型，可存储纯文本或 JSON 格式的追溯详情
3. **无独立查询接口**：通过药材详情一并获取，无按追溯码反查等功能
4. **无批次粒度**：追溯信息绑定在药材 SKU 维度，不区分批次/批次号

## 四、补充说明

### 4.1 前后端分离架构

系统保持前后端完全分离，三端独立部署：

| 端 | 技术栈 | 目录 |
|----|--------|------|
| 后端 | Spring Boot + MyBatis Plus + MySQL + Redis | `backend/` |
| 管理端 | Vue 3 + Element Plus + Vite | `frontend-admin/` |
| 用户端 | Vue 3 + Element Plus + Vite | `frontend-user/` |

每端均有独立的 `Dockerfile`，通过 `docker-compose.yml` 统一编排。

### 4.2 代码命名约定

所有代码保持原命名风格：
- 后端：Java 驼峰命名，实体类 `XxxInfo`，服务 `XxxService`，控制器 `XxxController`
- 前端：Vue 组件大驼峰，API 文件小驼峰
- 数据库：下划线命名，表名 `xxx_info`
